# Memory & context

## Purpose
Choose what context belongs in a task and what, if anything, should persist between sessions.

## Learning objectives
- Distinguish conversation context from persistent memory.
- Assess memory for relevance, freshness, sensitivity, and source.
- Define a review and deletion approach for stored information.

## Lesson
Context is information available to an agent while it works. Some context lasts only for one conversation; persistent memory carries selected information into later tasks. Memory can reduce repetition, but stale, incorrect, or sensitive information can mislead future work or expose data unnecessarily.

Store only information likely to improve a future task. Record where it came from, when it was checked, and whether it is a fact, preference, or assumption. Prefer concise, relevant notes over conversation dumps. Avoid storing secrets or personal information without a clear need and appropriate handling.

Memory needs maintenance. Provide a way to inspect, correct, and delete it. Revalidate information that can change, and make uncertainty visible when memory is used. For many tasks, retrieving current source material is safer than trusting a persistent note.

## Key takeaways
- Short-term context lives within one working session.
- Persistent memory should be reviewed and corrected.
- Relevant context is usually more useful than more context.

## Try it
List three facts an agent might usefully remember and one it should forget. For each retained fact, state its source, sensitivity, review date, and deletion method.

## Check your understanding
1. Name two risks of persistent memory.
2. What information should accompany a stored fact so it can be assessed later?
