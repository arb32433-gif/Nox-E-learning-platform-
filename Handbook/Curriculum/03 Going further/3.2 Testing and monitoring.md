# Testing & monitoring

## Purpose
Create a small evaluation set and monitoring plan before trusting a workflow.

## Learning objectives
- Build representative test cases with expected outcomes.
- Measure correctness, failure handling, and tool behavior.
- Select signals for quality, errors, latency, and cost.

## Lesson
Testing checks whether a workflow behaves as intended before it affects real work. Build realistic examples, including ordinary cases, ambiguous requests, missing information, and inputs the agent should refuse or escalate. Write expected outcomes before running tests so evaluation does not depend on whether an answer merely sounds plausible.

Check the whole workflow: task understanding, tool choice, tool-error handling, permission boundaries, and usability of the result. Include cases where the correct behavior is to ask a question or stop. Re-run the set after changing prompts, tools, models, or data sources.

After launch, monitor outcomes over time. Signals can include error and escalation rates, human edits, completion time, and cost per completed task. A successful-looking response can hide a silent failure, so sample results and compare them with source records. Define thresholds that pause or route the workflow for review when performance degrades.

## Key takeaways
- Build a small test set from realistic tasks.
- Watch for silent failures that appear successful.
- Track cost per completed task alongside quality and reliability.

## Try it
Write five representative inputs. For each, record expected behavior, including an ambiguous case and one where the agent should stop. Choose two signals to monitor after launch.

## Check your understanding
1. Why write expected outcomes before running tests?
2. Name one signal that can reveal a silent quality problem.
