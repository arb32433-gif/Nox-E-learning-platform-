# Ship your first workflow

## Purpose
Plan a bounded first workflow that combines delegation, tools, safeguards, and evaluation.

## Learning objectives
- Select a repetitive task with a clear outcome and manageable risk.
- Map steps, roles, data, tools, checks, and approval points.
- Define a sample-data pilot and a review after launch.

## Lesson
A good first workflow solves one real, repeated problem with a result you can verify. Keep scope narrow: one goal, limited data, few tools, and a clear completion condition. Map the manual process before deciding what to automate.

For each step, specify who or what performs it, required input, expected output, and how the output is checked. Mark actions needing a person to approve, edit, or stop the process. Include a fallback for missing information, tool failure, or an unexpected result. Use sample data first and record known examples for evaluation.

Pilot with limited scope. Review quality, exceptions, user effort, and cost before expanding access or autonomy. Keep a named owner responsible for reviewing results and changing or pausing the workflow when assumptions no longer hold.

## Key takeaways
- Choose one task you repeat and can verify.
- Run it on sample data before using real data.
- Review results after a pilot and adjust the workflow.

## Try it
Write your workflow in five steps. For each, name the actor, input, output, and check. Mark the approval point, failure fallback, and three sample cases to use before a limited pilot.

## Check your understanding
1. What makes a task suitable as a first workflow?
2. Name two conditions that should pause the workflow for review.
