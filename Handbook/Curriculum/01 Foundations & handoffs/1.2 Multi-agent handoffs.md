# Multi-agent handoffs

## Purpose
Design a clear handoff so another agent can continue work without guessing.

## Learning objectives
- Describe when splitting work across agents may help.
- Write a handoff with goal, completed work, evidence, and open questions.
- Keep ownership and completion criteria explicit.

## Lesson
A multi-agent workflow divides a larger job into roles. One agent might gather evidence, another draft, and a reviewer check the result. This can clarify responsibilities, but every handoff creates a chance to lose context or introduce inconsistent assumptions.

A handoff is a compact working brief. Include the shared goal, receiving role, completed work, evidence or source material, constraints, unresolved questions, and expected output. Separate facts from assumptions. If the next agent cannot tell what to do or how success will be judged, the handoff is incomplete.

Keep a person or designated coordinator responsible for the overall outcome. Agents should report what they did and what remains. Use the smallest number of roles that makes the work clearer.

## Key takeaways
- Give each agent one clear role.
- Write context down because it can be lost at handoffs.
- A router or coordinator selects the right recipient for a request.

## Try it
Write a handoff brief for a small task: goal, recipient role, completed work, sources, constraints, open questions, and definition of done. Ask someone unfamiliar with it what remains unclear.

## Check your understanding
1. What information should travel with a handoff?
2. Who remains accountable for the final result?
