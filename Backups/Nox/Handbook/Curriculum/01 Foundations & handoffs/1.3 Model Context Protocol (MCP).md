# Model Context Protocol (MCP)

## Purpose
Understand MCP's client/server model and plan access for an agent-connected tool.

## Learning objectives
- Identify the MCP client, server, and exposed capabilities.
- Distinguish reading data from changing it.
- Define least-privilege access for a proposed integration.

## Lesson
The Model Context Protocol (MCP) is an open protocol for connecting AI applications to external context and capabilities. An AI application commonly acts as the **client** and connects to an MCP **server**. The server exposes capabilities such as tools, resources, or prompts; the client can discover and use them according to the integration and permissions in place.

MCP standardizes how these pieces communicate. It does not make a connected tool inherently safe, guarantee its output, or grant permission by itself. The server and connected service still determine what data can be accessed and which actions can be performed.

Design access around the task. Begin with the narrowest useful scope, prefer read-only access while exploring, and require confirmation for consequential writes or external actions. Review what data is sent, where credentials are held, and how actions are logged. Test with synthetic or non-sensitive data first.

## Key takeaways
- An MCP server exposes capabilities; an MCP client connects to them.
- Permissions determine what an agent can read or change.
- Start read-only and widen access only when the task requires it.

## Try it
List three tools you use every day. For each, note needed data, permitted reads, changes it must never make, and actions requiring approval.

## Check your understanding
1. Does MCP itself guarantee that an exposed tool is safe?
2. Why is read-only access a useful starting point?
